## Goal (Wave 1)

Produce an executable UAT checklist and evidence capture convention, and validate the deterministic LuaSocket TCP check on macOS onPC using a mock bridge (no hardware required). This wave prepares Wave 2 hardware runs and ensures Phase 5 deferred UI tests are explicitly queued for execution.

## Evidence bundle conventions (Phase 7)

### Evidence root

- `.planning/phases/07-console-uat-hardware-validation/evidence/<run_id>/`

### `run_id` format

- `YYYYMMDD_onpc-<version>_mac-<model>_bridge-<mock|real>[_notes]`
- Example: `20260702_onpc-1.6.1.3_mac-m2pro_bridge-mock`

### Required artifacts produced by this plan

- `env.md` (environment + topology declaration for TOP-01)
- `bridge_status_mock.txt` (terminal output of `/status`)
- `screens/luasocket_check_success.png` OR `screens/luasocket_check_luasocket_unavailable.png` (deterministic UAT-02 indicator)
- `screens/bridge_error_connection_refused.png` (bridge-down error proves LuaSocket present)
- `screens/remote_offer_dialog.png` (remote offer gate visible when bridge configured)
- `screens/measurement_received_mock.png` (UAT-03 UI proof in mock mode; hardware proof deferred to Wave 2)
- `notes_wave1.md` (any deviations + blockers)

### Task 3 — Deterministic LuaSocket check on onPC (no hardware required)

<read_first>
- `/workspace/.planning/phases/07-console-uat-hardware-validation/07-RESEARCH.md` (A2, deterministic interpretation)
- `/workspace/.planning/phases/05-ma3-http-integration/05-UAT.md` (tests 2–4)
</read_first>

<action>
- In GrandMA3 onPC on macOS:
  - Ensure plugin `config.json` points to `bridge_ip: "127.0.0.1"` and `bridge_port: 8765` (TOP-01).
  - Reach the first measurement dialog in a C-7000 session and confirm the remote offer UI exists.
  - Execute the LuaSocket determinism check:
    - Stop the bridge and attempt Remote Measurement once to induce a connection error.
    - Start the mock bridge and attempt Remote Measurement once to get a successful measurement receipt UI.
- Capture screenshots:
  - `screens/bridge_error_connection_refused.png` (bridge stopped)
  - `screens/remote_offer_dialog.png` (remote offer buttons)
  - `screens/measurement_received_mock.png` (values displayed)
  - If LuaSocket is missing: `screens/luasocket_check_luasocket_unavailable.png`
  - If LuaSocket works: `screens/luasocket_check_success.png` (can be the successful measurement or the connection-refused error that is not `luasocket_unavailable`)
</action>

<verify>
- UAT-02 PASS condition is demonstrated by either:
  - a non-`luasocket_unavailable` bridge-down error (e.g. connection refused), and/or
  - a successful remote measurement after starting the bridge.
- If `luasocket_unavailable` is observed, treat UAT-02 as FAIL and record it in `notes_wave1.md` with the onPC version.
</verify>

<acceptance_criteria>
- The run evidence contains screenshots that let a reviewer independently conclude whether LuaSocket TCP works on the target onPC build.
</acceptance_criteria>
