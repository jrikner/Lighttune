## Goal (Wave 2)

Run the ship-gate UAT end-to-end on **macOS onPC + localhost bridge + C-7000 USB** (TOP-01) and produce a reviewer-ready evidence bundle proving UAT-01/02/03, including timing (<5 minutes target) plus at least one controlled error-path proof. Also execute Phase 5’s deferred on-console tests and attach the resulting artifacts into Phase 7 evidence.

## Preconditions

- Same or new evidence bundle directory as Wave 1:
  - `.planning/phases/07-console-uat-hardware-validation/evidence/<run_id>/`
  - Use `bridge-real` in `<run_id>` for Wave 2.
- GrandMA3 onPC build is the intended production target (record version in `env.md`).
- `config.json` is loaded correctly by the plugin and points to:
  - `bridge_ip: "127.0.0.1"`
  - `bridge_port: 8765`
- C-7000 is physically connected via USB to the same Mac that runs the bridge.

## Tasks

### Task 1 — Real bridge bring-up (C-7000 USB) + `/status`/`/measure` confirmation

<read_first>
- `/workspace/.planning/phases/07-console-uat-hardware-validation/07-CONTEXT.md` (TOP-01)
- `/workspace/.planning/REQUIREMENTS.md` (UAT-01/02/03, TOP-01)
</read_first>

<action>
- Start the bridge in real mode on macOS:
  - `cd sekonic-bridge`
  - `python3 server.py --port 8765`
- Capture:
  - `curl http://127.0.0.1:8765/status` → `bridge_status_real.txt`
  - `curl -X POST http://127.0.0.1:8765/measure` → `bridge_measure_real.txt`
  - Copy bridge runtime logs if present → `bridge.log` (or `bridge_log.txt` if renamed)
- If `/measure` fails, capture the exact error response and include it in `notes_wave2.md` (do not hide failures; this is ship gate).
</action>

<verify>
- `/status` indicates bridge is alive on localhost.
- `/measure` returns at least `cct`, `duv`, `cri`, `r9`; if `tlci` is present, record it as part of UAT-03 proof.
</verify>

<acceptance_criteria>
- Evidence bundle contains `bridge_status_real.txt` and either a successful `bridge_measure_real.txt` or a clearly documented failure with logs and next-action notes.
</acceptance_criteria>

### Task 2 — Execute Phase 5 deferred on-console tests (on macOS onPC)

<read_first>
- `/workspace/.planning/phases/05-ma3-http-integration/05-UAT.md` (tests 1–7)
- `/workspace/.planning/phases/05-ma3-http-integration/05-VERIFICATION.md` (human verification items)
</read_first>

<action>
Execute the following on-console tests, capturing the specified artifacts:

- **T1 Bridge Status — auth and last error**
  - Navigate main menu → Bridge Status.
  - Capture `screens/bridge_status.png` showing reachability and any auth/last-error lines.
- **T2 C-7000 remote offer gate**
  - In a C-7000 session, reach first measurement dialog.
  - Capture `screens/remote_offer_dialog_real.png`.
- **T3 Remote measure — first attempt flow**
  - Choose Remote Measurement and accept returned values.
  - Capture `screens/measurement_received_real.png` with values visible (including TLCI if present).
- **T4 Bridge error — enriched UX**
  - Induce one controlled error (pick one):
    - stop the bridge, or
    - use wrong port, or
    - unplug meter (only if safe), or
    - auth mismatch if the build supports API key.
  - Capture `screens/bridge_error_real.png` showing error and Retry/Manual/Cancel options.
- **T5 Auto-loop — per-cycle confirm**
  - After first accepted remote measure, allow auto-loop to prompt at least once.
  - Capture `screens/auto_loop_confirm.png` showing Accept/Manual/Cancel.
- **T6 Auto-loop — stuck after 3 attempts**
  - If achievable on your fixtures, run 3 cycles without meeting goals to trigger stuck dialog.
  - Capture `screens/auto_loop_stuck_after_3.png`.
- **T7 Bridge Setup wizard preserved (if exposed in this build)**
  - Run discover/capture/learn_trigger flow if available.
  - Capture `screens/bridge_setup_steps.png` and any completion flags.

Record the test results (pass/fail + notes + which artifacts) in `phase5_deferred_tests.md` inside the run evidence folder.
</action>

<verify>
- Every Phase 5 deferred test has:
  - an explicit result (pass/fail/blocked),
  - at least one artifact reference, and
  - notes on any deviations.
</verify>

<acceptance_criteria>
- `phase5_deferred_tests.md` exists and Phase 5 deferred tests have reviewer-checkable screenshots for each executed case.
</acceptance_criteria>

### Task 3 — Ship-gate UAT: one end-to-end single-group run with timing and acceptance labeling

<read_first>
- `/workspace/.planning/phases/07-console-uat-hardware-validation/07-CONTEXT.md` (UAT-01 + <5 minute target + acceptance override)
- `/workspace/.planning/ROADMAP.md` (Phase 7 success criteria)
</read_first>

<action>
- Choose a controlled test showfile and fixture group (record group ID + fixture make/model in `env.md`).
- Start a timer at “Start Calibration”.
- Complete one group end-to-end using remote measurements from the real bridge:
  - measure (remote) → assess → apply → re-measure (remote) at least once → finish group.
- If goals are not met but the operator accepts, label this as an **acceptance override** and record the reason.
- Capture:
  - `video/uat01_single_group_e2e.mp4` (screen recording from first remote measurement through group completion)
  - `screens/session_summary_or_group_done_real.png`
  - `timing.csv` containing: `run_id,start_ts,end_ts,elapsed_s,group_id,fixture_make,fixture_model,goals_summary,pass_or_override,notes`
</action>

<verify>
- Video shows the remote measurement trigger and values display (UAT-03), and completion of the group (UAT-01).
- Timing evidence supports the <5 minute claim or documents the blocker and whether acceptance override was used.
</verify>

<acceptance_criteria>
- Evidence bundle contains `video/uat01_single_group_e2e.mp4`, `timing.csv`, and `screens/session_summary_or_group_done_real.png` with clear pass/override labeling.
</acceptance_criteria>
